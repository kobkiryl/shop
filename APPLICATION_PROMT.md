# Shop Card Application - Recreation Instructions

This document contains step-by-step instructions to recreate the Family Shop Card Service application from scratch.

## Project Overview

Build a RESTful API for managing family shop cards using Spring Boot, Java 17, and Gradle.

**Key Features:**
- CRUD operations for shop cards
- Basic authentication with user ownership
- Pagination and sorting support
- H2 in-memory database
- Comprehensive test coverage

## Technology Stack

- **Spring Boot**: 3.5.6
- **Java**: 17
- **Build Tool**: Gradle 8.14.3
- **Database**: H2 (in-memory)
- **Security**: Spring Security with Basic Auth
- **Testing**: JUnit 5, Spring Boot Test

## Step-by-Step Implementation

**Project Settings:**

### 6. Domain Model

**File:** `src/main/java/example/shopcard/ShopCard.java`

Create a Java record to represent a shop card entity:
- Use `@Id` annotation for the id field
- Include fields: `Long id`, `Double amount`, `String owner`
- This will be a simple immutable record class

### 7. Repository Layer

**File:** `src/main/java/example/shopcard/ShopCardRepository.java`

Create an interface that extends both `CrudRepository` and `PagingAndSortingRepository`:
1. Extend `CrudRepository<ShopCard, Long>` for basic CRUD operations
2. Extend `PagingAndSortingRepository<ShopCard, Long>` for pagination support
3. Add custom query methods:
   - Find a shop card by id and owner
   - Find all shop cards by owner with pagination
   - Check if a shop card exists by id and owner

**Spring Data Repository Notes:**
- Spring Data automatically implements these interfaces at runtime
- Method names follow Spring Data naming conventions for automatic query generation
- No need to write SQL - Spring Data derives queries from method names

### 8. REST Controller

**File:** `src/main/java/example/shopcard/ShopCardController.java`

Create a REST controller with the following endpoints:

**Annotations:**
- `@RestController` - Marks class as REST controller
- `@RequestMapping("/shopcards")` - Base path for all endpoints

**Constructor Injection:**
- Inject `ShopCardRepository` via constructor

**Endpoints to implement:**

1. **GET /shopcards/{requestedId}**
   - Find shop card by id and owner (use Principal for owner)
   - Return 404 if not found or not owned by user
   - Return 200 with shop card data

2. **POST /shopcards**
   - Create new shop card with authenticated user as owner
   - Save to repository
   - Return 201 with Location header

3. **GET /shopcards**
   - List all shop cards for authenticated user
   - Support pagination: `?page=0&size=20`
   - Support sorting: `?sort=amount,desc`
   - Use `PageRequest.of(page, size, sort)` for pagination
   - Return 200 with list of shop cards

4. **PUT /shopcards/{requestedId}**
   - Update existing shop card
   - Check ownership before updating
   - Return 204 if successful, 404 if not found/not owned

5. **DELETE /shopcards/{requestedId}**
   - Delete shop card by id
   - Check ownership before deleting
   - Return 204 if successful, 404 if not found/not owned

**Security:**
- Use `Principal` parameter to get authenticated username
- Always filter operations by owner to ensure data isolation

### 9. Security Configuration

**File:** `src/main/java/example/shopcard/SecurityConfig.java`

Create a security configuration class:

**Annotations:**
- `@Configuration`
- `@EnableWebSecurity`

**Configure:**
1. Create a `SecurityFilterChain` bean
2. Disable CSRF (for REST API)
3. Require authentication for `/shopcards/**` endpoints
4. Require `CARD-OWNER` role
5. Use HTTP Basic authentication
6. Configure password encoder (BCrypt)

**Test Users:**

**Note:** Use BCrypt password encoder for password hashing.

### 13. Integration Tests

**File:** `src/test/java/example/shopcard/ShopcardApplicationTests.java`

Create comprehensive integration tests:

**Annotations:**
- `@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)`
- `@DirtiesContext(classMode = ClassMode.AFTER_EACH_TEST_METHOD)` - Reset DB after each test

**Dependencies:**
- Inject `TestRestTemplate` for making HTTP requests

**Authentication:**
- Use `.withBasicAuth(username, password)` on all requests
- Primary test user: `kiryl1` / `12345qwe`
- Secondary test user: `max1` / `qwerty1`
- Non-owner user: `hank-owns-no-cards` / `qrs456`

**Tests to implement:**

1. **shouldReturnAShopCardWhenDataIsSaved**

   - Verify 200 OK response
   - Verify id=99 and amount=987.56

2. **shouldNotReturnAShopCardWithAnUnknownId**
   - GET /shopcards/1000
   - Verify 404 NOT FOUND response

3. **shouldCreateANewShopCard**
   - POST /shopcards with new shop card (amount=300.00)
   - Verify 201 CREATED response
   - Verify Location header is present
   - GET the new shop card and verify amount=300.00

4. **shouldCreateANewShopCardWithPredefinedId**
   - POST /shopcards with predefined id
   - Verify card is created and retrievable

5. **shouldReturnAllShopCardsWhenListIsRequested**
   - GET /shopcards
   - Verify 200 OK response
   - Verify 3 cards returned for kiryl1
   - Verify ids: 99, 100, 101
   - Verify amounts: 987.56, 1.00, 150.00

6. **shouldReturnAPageOfShopCards**
   - GET /shopcards?page=0&size=1
   - Verify 200 OK response
   - Verify only 1 card returned

7. **shouldReturnASortedPageOfShopCards**
   - GET /shopcards?page=0&size=1&sort=amount,desc
   - Verify 200 OK response
   - Verify highest amount (987.56) is returned

8. **shouldRejectUsersWhoAreNotCardOwners**
   - GET /shopcards/99 as "hank-owns-no-cards"
   - Verify 403 FORBIDDEN response

9. **shouldNotAllowAccessToCardsTheyDoNotOwn**
   - GET /shopcards/102 as kiryl1 (owned by max1)
   - Verify 404 NOT FOUND response

10. **shouldUpdateAnExistingShopCard**
    - PUT /shopcards/99 with new amount (19.99)
    - Verify 204 NO CONTENT response
    - GET /shopcards/99 and verify amount=19.99

11. **shouldNotUpdateAShopCardThatDoesNotExist**
    - PUT /shopcards/99999
    - Verify 404 NOT FOUND response

12. **shouldNotUpdateAShopCardOwnedBySomeoneElse**
    - PUT /shopcards/102 as kiryl1 (owned by max1)
    - Verify 404 NOT FOUND response

13. **shouldDeleteAnExistingShopCard**
    - DELETE /shopcards/99
    - Verify 204 NO CONTENT response
    - GET /shopcards/99 and verify 404 NOT FOUND

14. **shouldNotDeleteAShopCardThatDoesNotExist**
    - DELETE /shopcards/99999
    - Verify 404 NOT FOUND response

15. **shouldNotAllowDeletionOfCardsTheyDoNotOwn**
    - DELETE /shopcards/102 as kiryl1 (owned by max1)

**Testing Tips:**
- Use JsonPath to parse JSON responses
- Use AssertJ assertions (`assertThat`)
- Always include authentication on requests
- Test both positive and negative scenarios
- Verify proper HTTP status codes

## Running the Application

### Build and Test
```bash
# Build the project
./gradlew build

# Run all tests
./gradlew test

# Run specific test class
./gradlew test --tests ShopcardApplicationTests
```

### Run the Application
```bash
./gradlew bootRun
```

### Test the API
```bash
# Get a shop card
curl -u kiryl1:12345qwe http://localhost:8080/shopcards/99

# Create a shop card
curl -u kiryl1:12345qwe -X POST http://localhost:8080/shopcards \
  -H "Content-Type: application/json" \
  -d '{"amount": 50.00, "owner": "kiryl1"}'

# List all shop cards
curl -u kiryl1:12345qwe http://localhost:8080/shopcards

# Update a shop card
curl -u kiryl1:12345qwe -X PUT http://localhost:8080/shopcards/99 \
  -H "Content-Type: application/json" \
  -d '{"amount": 75.00}'

# Delete a shop card
curl -u kiryl1:12345qwe -X DELETE http://localhost:8080/shopcards/99
```
